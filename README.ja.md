# Tricloud

[English](README.md) | [日本語](README.ja.md) | [Español](README.es.md)

Tricloudは、Web3・分散型ストレージの考え方を取り入れた、Windows向けのベータ版デスクトップクラウドストレージアプリです。

Tricloudは、「クラウドストレージは、大規模な集中型ストレージ事業者だけに依存しなくてもよいのではないか」という発想をもとに開発しています。

ユーザーはクラウドストレージを利用するだけでなく、自分のパソコンで余っているストレージ容量をネットワークへ提供できます。将来的には、多数のユーザーがストレージ容量を持ち寄り、提供量や稼働状況などに応じて報酬を受け取れるサービスを目指しています。

現在の公開ベータ版では、基本的なクラウドストレージ機能に加えて、ストレージ提供者機能のテストも開放しています。

> \*\*状態:\*\* 公開ベータ / 初期プロトタイプ  
> \*\*バージョン:\*\* `v0.1.0-beta`  
> \*\*対応OS:\*\* Windows  
> \*\*分類:\*\* Web3の考え方を取り入れた分散型ストレージ  
> \*\*安定性:\*\* 実験段階  
> \*\*推奨用途:\*\* テスト目的のみ  
> \*\*重要:\*\* 重要なファイルや失うと困るファイルの唯一の保存先としては、まだ使用しないでください。

\---

## ⚠️ 重要：現在のベータテストでは報酬は支払われません

# **現在のベータテストでは、ストレージを提供しても、金銭・暗号資産・トークンその他の報酬は一切支払われません。**

ストレージ提供者機能のテストは、技術的な動作、操作性、接続性、安定性を確認するためのものです。

ベータテストへの参加、ストレージの提供、ノードの稼働によって、将来的な報酬を受け取る権利が発生するものではありません。

## TricloudとWeb3の関係

Tricloudでは、ユーザーが自分のパソコンの空きストレージを提供し、他のユーザーがそのストレージをクラウドストレージとして利用できる仕組みを目指しています。

以下の点で、Web3や分散型サービスの考え方を取り入れています。

* ユーザー自身がネットワークへストレージ容量を提供できる
* 利用者だけでなく、ストレージ提供者としてもサービスに参加できる
* 特定の大規模ストレージ事業者だけに保存容量を依存しない
* 複数の参加者が提供するストレージをサービスに活用する
* 将来的に、ストレージ提供への報酬を導入する

ただし、**Tricloudで分散化の対象となるのは、ストレージの提供と利用に関する部分です。**

認証、アカウント情報、ファイルメタデータ、ノード管理、ストレージ配置の調整などは、中央の管理サーバーによって処理されます。Tricloud全体を完全に分散化する計画はありません。

そのため、Tricloudは完全分散型のdAppではなく、Web3・分散型ストレージの考え方を、ストレージの提供と利用に取り入れたクラウドストレージサービスです。

## ブロックチェーンなどの技術について

現在のTricloudでは、以下の技術を使用していません。

* ブロックチェーン
* 独自トークン
* ユーザー向け暗号資産ウォレット
* スマートコントラクト
* NFT
* DAOによるサービス運営
* ブロックチェーン上でのアカウント・ファイル管理

これらの技術は、現在のTricloudに必要なものではないと考えているため、通常想定している将来計画でも実装する予定はありません。

Tricloudの管理サーバー、ユーザー認証、メタデータ管理、ストレージ配置、報酬計算などを、ブロックチェーンやスマートコントラクトへ移行する計画もありません。

将来、Tricloudが独自のパソコンやスマートフォンなどを展開し、サービスの構造そのものが大きく変わる場合には、必要な技術を改めて検討する可能性があります。しかし、現在開発しているクラウドストレージサービスの範囲では、ブロックチェーン、独自トークン、ウォレット、スマートコントラクトを導入する予定はありません。

### 暗号資産による支払いについて

将来、暗号資産が既存通貨と同程度に、法的・技術的・運用的に扱いやすい決済手段となった場合には、ストレージ料金の支払いやストレージ提供報酬の受取方法の一つとして、既存の暗号資産へ対応する可能性があります。

ただし、これは日本円、米ドル、クレジットカード、銀行振込などに並ぶ決済・送金手段を追加するものであり、以下を意味するものではありません。

* Tricloud独自トークンの発行
* Tricloud専用ウォレットの提供
* スマートコントラクトによるサービス運営
* ファイル情報やユーザー情報のブロックチェーン保存
* Tricloud自体のブロックチェーンアプリ化

## ストレージ提供者機能

ストレージ提供者機能では、自分のパソコンの空きストレージ容量の一部をTricloudのテストネットワークへ提供できます。

現在のベータ版では、以下の流れで利用します。

1. 提供するストレージ容量を入力する
2. 設定を保存する
3. ストレージの提供を開始する
4. ノードの起動状態を確認する
5. 必要に応じてストレージ提供を停止する

現在の配布版では、必要なPython実行環境とノード用backendをアプリ側に含める構成としているため、通常はPythonを手動で準備する必要はありません。

ストレージ提供中にインターネット接続やWi-Fiが一時的に切断された場合は、接続回復後にDataServerへの再接続を試みます。ただし、ネットワーク環境によっては、オンライン状態へ戻るまでに時間がかかる可能性があります。

### ベータテスト中の報酬について

# **現在のベータテストでは、ストレージを提供しても報酬は支払われません。**

このテストは、以下の検証を目的としています。

* 他のWindowsパソコンでノードを起動できるか
* 提供開始と停止が正しく動作するか
* ネットワーク切断後に再接続できるか
* ストレージ提供量を正しく認識できるか
* 長時間稼働できるか
* 利用者にとって設定手順が分かりやすいか

ベータテストへの参加は、将来的な報酬の支払いを保証するものではありません。

## 現在の仕組み

現在のTricloudは、大まかに以下の構成で動作しています。

* Electron、React、TypeScript、Tailwind CSSによるWindowsデスクトップアプリ
* アプリに同梱されたPython実行環境
* アプリに同梱されたストレージ提供ノード用backend
* FastAPIによるControl API
* アカウント情報やファイルメタデータを管理するPostgreSQL
* ストレージ通信を担当するDataServer
* NginxによるHTTPSアクセス
* ZeroMQによるDataServerとノード間の通信
* Google Cloud VM上で稼働する現在のベータ管理サーバー
* ユーザーのパソコン上で稼働するストレージ提供ノード

現在のTricloudは、中央の管理サーバーと、ユーザーが提供するストレージノードを組み合わせた構成です。

中央の管理サーバーは、認証、メタデータ、ノード情報、ストレージ配置などを管理します。ユーザーが提供するノードは、ファイルデータを保存するためのストレージ容量を提供します。

中央管理部分をブロックチェーンなどへ置き換える計画はありません。

## インストール方法

### Installer版（`v0.1.0-beta`）

1. GitHub ReleasesページからInstaller版をダウンロードします。
2. インストーラーを実行します。
3. Windows SmartScreenの警告が表示された場合は、公式のTricloud GitHub Releaseからダウンロードしたファイルであることを確認したうえで、続行するか判断してください。
4. アプリ本体、backend、実行環境がセットアップされるまで待ちます。
5. スタートメニューまたはデスクトップショートカットからTricloudを起動します。
6. アカウントを作成するか、既存アカウントでログインします。
7. 機密情報を含まない小さなテスト用ファイルで、アップロードとダウンロードを確認します。

### Portable版

現在のPortable版は正常に起動せず、`Invalid file descriptor to ICU data received.` が表示されるため、`v0.1.0-beta` では配布しません。

### Pythonについて

通常、利用者がPythonを別途インストールする必要はありません。

Installer版には、ストレージ提供機能に必要なPython実行環境とbackendファイルが含まれています。

古いテスト版には必要なファイルがすべて含まれていない可能性があるため、GitHub Releasesから最新のビルドを使用してください。

## 確認済み環境

`v0.1.0-beta` は、以下のCPUを搭載した2台のWindows 11 x64パソコンで動作確認しています。

* 12th Gen Intel(R) Core(TM) i5-1240P
* Intel(R) Core(TM) i3-7020U

確認済みの内容は以下です。

* Installer版のインストールとアンインストール
* 数秒での起動
* アカウント作成とログイン
* 小容量およびやや大きいファイルのアップロード
* ダウンロード後のファイル内容が元ファイルと一致すること
* 自動バックアップでファイル・フォルダの変更が反映されること
* オフライン利用中の変更が再接続後に反映されること
* ストレージ提供の開始、停止、再起動、再接続
* Tricloudを完全終了して再起動した後も、通常の操作を継続できること

Windows 10、Windows on ARM64、その他の環境は未確認です。上記CPUは動作確認に使用した環境であり、最低動作要件を示すものではありません。

## 初回テストの流れ

アプリを起動したら、まず以下を試してください。

1. 新しいアカウントを作成する
2. ログインする
3. 小さなテスト用ファイルをアップロードする
4. そのファイルをダウンロードする
5. アプリを一度終了する
6. アプリを再起動する
7. 再ログイン後、ファイル一覧が表示されるか確認する

ストレージ提供者機能を試す場合は、さらに以下を確認してください。

1. 提供する容量を入力する
2. 設定を保存する
3. ストレージ提供を開始する
4. ノードがオンラインになるか確認する
5. 一度提供を停止する
6. 再度開始できるか確認する
7. 可能であれば、Wi-Fiを一時的に切断する
8. Wi-Fi復帰後にノードが再接続するか確認する

ストレージ提供者機能は、重要なデータが入っていないテスト環境で試してください。

## 既知の制限

このベータ版には、以下の制限があります。

* 現在確認済みの環境はWindows 11 x64のみです。Windows 10とWindows on ARM64は未確認です。
* アプリはコード署名されておらず、Windows SmartScreenの警告が表示されます。
* Portable版は `Invalid file descriptor to ICU data received.` により起動できないため、`v0.1.0-beta` には含めません。
* 未確認のパソコンでは、初回起動や実行環境の準備に時間がかかる場合があります。
* 確認済みの2環境ではMicrosoft Defenderによる遮断は発生しませんでしたが、別の環境やセキュリティ製品では、同梱されたPython実行環境やノードプロセスが確認・遮断される可能性があります。
* テスト期間中、管理サーバーの保守、更新、再起動、障害などにより、一時的にサービスを利用できない場合があります。
* ベータ期間中の仕様変更やデータベース更新により、アカウント情報や保存したテストデータが削除・初期化される可能性があります。
* 稼働率、保存継続期間、データ復旧、データ復元に関する保証やSLAはありません。
* アップロード、ダウンロード、自動バックアップ、オフライン利用の仕様は変更される可能性があります。
* ストレージ提供者機能は実験段階です。
* **現在のベータテストでは、ストレージを提供しても報酬は支払われません。**
* ネットワーク復帰後、ノードの再接続に時間がかかる場合があります。
* 一部のUIやエラー表示は未完成です。
* 大規模ユーザー環境での性能検証は十分ではありません。
* Tricloudは、管理サーバーを含む完全分散型システムではありません。
* 重要なデータ、機密データ、個人情報を含むファイルの保存には使用しないでください。
* 重要なファイルの唯一の保存先として使用しないでください。

1. 提供量や稼働状況に応じて報酬額が決まる計量制
2. 提供量や稼働状況を当選率に反映する、宝くじのような抽選制

どちらの方式が魅力的か、または別の方式がよいか、意見を募集しています。

ただし、抽選性のある方式は、国や地域によって法的・規制上の問題が生じる可能性があります。

そのため、抽選制への支持が多かった場合でも、法的確認の結果、提供量や稼働状況に応じた計量制を採用する可能性があります。
